# Проектная работа

**Тема проекта**: "Отказоустойчивая CMS-платформа QP8.CMS для корпоративных сайтов: архитектура на Kubernetes, Ceph и PostgreSQL с автоматизированным развертыванием"

**Цель проекта**: Построить отказоустойчивый кластер виртуализации для запуска современных сервисов, рассчитанных под высокую нагрузку 

---
### **Описание проекта**

В качестве сервиса для запуска выбрана отечественная CMS-платформа **QP8.CMS**.

**QP8.CMS** — это система управления контентом (CMS) с открытым исходным кодом, разработанная компанией Quantum Art. Она позволяет создавать и управлять структурой данных и содержимым сайтов, а также строить внутренние порталы

В качестве среды запуска используется система управления контейнерами Kubernetes (далее k8s), построенная на базе отказоустойчивого кластера. Использование среды k8S позволяет обеспечить весь жизненный цикл сервиса: от пуска до масштабирования и восстановления после сбоев. 

Общая архитектура системы представлена на диаграмме

[Diagram](https://viewer.diagrams.net/?tags=%7B%7D&lightbox=1&highlight=0000ff&edit=_blank&layers=1&nav=1&title=SystemDesign.drawio&dark=auto#Uhttps%3A%2F%2Fraw.githubusercontent.com%2Ffueller-max%2FOtus_HL_Project%2Fmain%2FDesign%2FSystemDesign.drawio#%7B%22pageId%22%3A%22A5w-lTScNQMh_YW98whM%22%7D)

Инфраструктура построена на базе нескольких взаимосвязанных компонентов с акцентом на отказоустойчивость и высокую доступность. Все сервисы защищены межсетевым экраном и организованы в отдельные VLAN для изоляции трафика

---

### 1. Кластер k8s
Как было указано, ядро системы - отказоустойчивый кластер k8s, построенный на базе 5 виртуальных машин (далее ВМ).

В состав кластера k8s входят:

* **Control Plane** (3 мастер-ноды):  
    * Обеспечивает управление кластером через API-серверы  
    * Реализована отказоустойчивость через HAProxy + Keepalived
    *  Доступ к API через VIP: 10.10.30.100
    * Ноды:  
        * Kub-Master-1 (10.10.30.48)  
        * Kub-Master-2 (10.10.30.49)  
        * Kub-Master-3 (10.10.30.50)   
* Worker nodes (2 ноды):  
    * Worker node 1 (10.10.30.53)
    * Worker node 2 (10.10.30.54)

* Работает в VLAN30 (10.10.30.0/24)

Таким образом, архитектура кластера позволяет сохранять работоспобность при выходе из строя любой из нод, за счет перераспределения нагрузки (в случае Worker Nodes) или перебаланисровки запросов.


### 2. PostgreSQL кластер

В качестве базы данных выбрана система PostgeSQL. Для реализации отказоустойчивости PostgeSQL также развернут в кластерном режиме.

Высокодоступное решение на базе:  
* Patroni для автоматического failover
* etcd как распределенное хранилище конфигурации
* HAProxy + Keepalived для балансировки

* Три ноды обеспечивают:  
  * Репликацию данных в реальном времени
  * Автоматическое переключение при сбоях
  * Балансировку нагрузки
<br></br>
* Доступ через VIP: 10.10.40.100  
* Работает в VLAN40 (10.10.40.0/24)  
  * Ноды:
    * PG-Node-1 (10.10.40.71)
    * PG-Node-2 (10.10.40.72)
    * PG-Node-3 (10.10.40.73)

### 3. Система хранения (Ceph)

* Распределенное хранилище с:
    * Тремя нодами (Ceph1, Ceph2, Ceph3)
    * Ролью мониторов и OSD на каждой ноде
    * Реплицированием данных

* Использует две сети:
    * VLAN80 (10.10.80.0/24) для управления
    * VLAN90 (10.10.90.0/24) для данных

* Ноды:
    * Ceph1 (10.10.80.91)
    * Ceph2 (10.10.80..92)
    * Ceph3 (10.10.80..93)

### 4. Система логирования (ELK)

* Elasticsearch кластер:  
  * Три ноды для отказоустойчивости
  * Реплицированные данные
  * Автоматическое обнаружение сбоев
  <br></br>  
* Kibana для визуализации логов  

* Работает в VLAN60 (10.10.60.0/24)
 * Компоненты:
   * ES-Node-1 (10.10.60.61)
   * ES-Node-2 (10.10.60.62)
   * ES-Node-3 (10.10.60.63)
   * Kibana (10.10.60.66)

### 5. Система мониторинга

Единый сервер с:  
* Prometheus для сбора метрик
* Grafana для визуализации

Расположен в VLAN70 (10.10.70.0/24)  
    IP: 10.10.70.80    

---

Для автоматизированного развертывания инфраструктуры используются следующие инструменты:

1. **Terrafrom** - автоматизированное развертывание виртуальных машин в гипервизоре Proxmox, базовая настройка ВМ (cloud-init)
2. **Ansible** - автоматизированный деплой программных пакетов и их настройка на хостах
3. **Docker Compose** -запуск мультиконтейнерных приложений (используется в деплое системы мониторинга)
